【三、技术硬约束（改代码时一条不许破）】
1. 改大文件先完整读取再精确编辑，禁止读完一小段就整文件覆盖。
2. 改数据库三件套：表类 + schemaVersion+1 + AppDatabase migration；
   用户表进 userTables 跳过集合；现有迁移链 v2(每日知识)→v3(已读/背诵)，
   本轮接 v4(章节学习)。
3. **drift 的 insertOnConflictUpdate 冲突目标只有主键 id**——带 uniqueKeys
   的表（ReadingProgress/DailyHistory/GlossaryProgress 等）重复写入必撞
   SqliteException 2067，幂等写入一律 delete-then-insert 或先查后插
   （README_FOR_AI 坑 13）。
4. drift where 闭包里不能把 Dart bool 与 Expression<bool> 用 || 混写；
   `?? const []` 不写类型会让循环变量变 dynamic，`int += dynamic` 报
   num→int——空列表兜底一律写 `const <具体类型>[]`。
5. drift 命名规则：Companion = 表类名+Companion；数据类名 = 表类名去尾 s
   （FaultDiagnosis→FaultDiagnosi）；不以 s 结尾的表数据类加 Data 后缀
   （SearchHistory→SearchHistoryData），不要直接引用后者的行类名。
6. Flutter 3.24：WidgetStateProperty / withOpacity；Record 不支持 []；
   ref.listen/ref.watch 只能在 build() 顶层或 provider 闭包；
   flutter_lints 把 info 也算失败（const/unused/多余 import 全要清）。
7. FTS5 trigram：<3 字符查询匹配不到任何行，仓库层 search() 已有 LIKE
   回退分支，直接查虚表的测试要用 ≥3 字词。
8. PowerShell 5.1 脚本只写 ASCII；**含中文的多行逻辑禁止用 python -c
   内联**（转义会静默失败）——写成 tool/*.py 或 workspace 的 _*.py
   脚本文件再执行。
9. 不引入新依赖、不改 applicationId（com.sunliangyu.brew_helper）、
   不改签名（keystore 只在 repo Secrets + tool/keystore_backup 备份）。
10. pubspec assets 目录声明不递归——新增书籍目录必须单列一行。

【五、容错】
1. 网络/CI"繁忙/超时/连接关闭/WebException"：等 3~5 分钟重试，连败
   3 次记录原因换下一子任务，不许卡死。
2. GitHub 次级限流 403（abuse detection）：push_incremental.py 已自动
   退避重试；若仍失败等 10 分钟再推，不许改全量 ps1 硬推。
3. CI 排队超 10 分钟：先做下一个本地批次，稍后回来轮询，不许空等。
4. artifact 找不到："No artifact found" 属预期（配额+continue-on-error），
   改走 apk-builds 分支下载，不算失败。
5. job 2 秒失败、0 步骤、无日志 = 账户级启动失败（曾因私有仓库分钟配额
   耗尽发生），看 check-run annotations 定位——现在是 public 仓库，
   若再现先查 billing 而不是改代码。
